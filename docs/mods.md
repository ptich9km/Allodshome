# Моды Allods Home

Мод — папка с данными: новые монстры, предметы, заклинания, здания и новые
**типы** контента (школа магии, категория брони, раса). Правки в коде игры не
нужны.

Пошаговое руководство «сделай первый мод»: `docs/mods-first.md`.

## Куда класть

| Что | Путь |
|---|---|
| Моды игрока | `user://mods/<id_мода>/` |
| Вшитые наборы | `res://mods/<id_мода>/` (для поставки с игрой, не для игрока) |

На Windows `user://` — это `%APPDATA%\Godot\app_userdata\Allods Home\`.
Точный путь: `ProjectSettings.globalize_path("user://mods")`, в игре — кнопка
«Открыть папку» в меню модов.

Папка внутри `mods/` должна называться **так же, как `id`** в манифесте.

## Структура

```
user://mods/warden/
  mod.json              # манифест, обязателен
  thumb.png             # превью в списке модов (необязательно)
  data/*.json           # записи: любые имена файлов, подпапки разрешены
  assets/*.png          # свои файлы, ссылки вида mod://warden/assets/x.png
```

## mod.json

```json
{
  "id": "warden",
  "name": "Сторож топей",
  "version": "1.0.0",
  "author": "твой ник",
  "description": "Новый зверь и его клык",
  "priority": 0,
  "affects_save": true,
  "depends_on": [],
  "load_after": []
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | Уникальный, = имя папки |
| `name` | нет | Отображаемое имя (по умолчанию `id`) |
| `version` | нет | Строка, пишется в сейв |
| `priority` | нет | Целое. **Больше = применяется позже = главнее** |
| `depends_on` | нет | Жёсткие зависимости: нет мода — этот не грузится |
| `load_after` | нет | Мягкий порядок: если такой мод есть, грузить после него |
| `affects_save` | нет | Мод меняет сохранение (по умолчанию `true`) |
| `thumb` | нет | Имя файла превью, по умолчанию `thumb.png` |

## Записи в данных

Файл в `data/` — это массив записей (или объект `{"entries": [...]}`).
Записи применяются в алфавитном порядке файлов.

```json
[
  {
    "into": "unit",
    "key": "monsters/warden",
    "extends": "monsters/wolf",
    "name_ru": "Сторож топей",
    "tier": 3,
    "palette": 5
  }
]
```

| Поле | Смысл |
|---|---|
| `into` | Куда класть: `item`, `unit`, `spell`, `structure`, `rule` |
| `key` | Ключ внутри базы |
| `op` | `add` (по умолчанию), `patch`, `remove`, `append` |
| `extends` | Взять базу как основу и перекрыть только указанные поля |

Остальные поля — данные самого объекта, ровно как в `assets/*/*.json`.

Поле называется `into`, а не `kind`, потому что `kind` есть у самих заклинаний
(`"kind": "attack"`) — иначе маршрутизация съедала бы их собственное поле.
Аналогично `type` у предмета — это тип предмета (`Long Sword`), а не база.

### into и ключи

| `into` | База | Ключ (`key`) |
|---|---|---|
| `item` | `assets/items/item_db.json` | имя предмета, напр. `Common warden fang` |
| `unit` | `assets/units/units_db.json` | имя набора, напр. `monsters/warden` |
| `spell` | `assets/spells/spells_db.json` | имя заклинания, напр. `Shadow_Bolt` |
| `structure` | `assets/structures/structure_db.json` | id здания числом в строке, напр. `900` |
| `rule` | `assets/config/content_rules.json` | точечный путь правила, напр. `spells.spheres` |

### op

- **`add`** — новый объект. Если ключ уже занят (игрой или другим модом) — это
  **ошибка**, запись пропускается. Для правки существующего нужен `patch`.
- **`patch`** — слить поля в существующий объект. Ключа нет — ошибка.
- **`remove`** — удалить объект.
- **`append`** — дописать элементы к списку в записи правил. Так добавляют новую
  школу магии или категорию брони, не переписывая весь список: перезапись легко
  затирает правки соседнего мода.

### extends

`extends` копирует существующий объект, а указанные рядом поля перекрывают.
Копия глубокая, вложенные словари сливаются по ключам, массивы заменяются.

```json
{"into": "unit", "key": "monsters/warden_t3", "extends": "monsters/wolf_t3",
 "name_ru": "Сторож топей", "resist": {"fire": 50}}
```

Порядок важен: `extends` ищет объект в базе **на момент применения записи**,
поэтому ссылаться можно на базу игры и на записи, применённые раньше (в том
числе из мода-зависимости).

## Свои ассеты

Любая строка, начинающаяся с `mod://<id>/`, разворачивается в папку мода:

```json
{"into": "item", "key": "Common warden fang", "type": "Dagger",
 "icon": "mod://warden/assets/fang.png", "damage_min": 7, "damage_max": 9}
```

- Файл должен существовать **на момент загрузки**. Нет файла — запись
  пропускается, в лог идёт ошибка с именем мода и путём. Розовых квадратов
  в игре не будет.
- Анимация монстра: `folder` набора тоже может быть
  `mod://warden/assets/units/warden`, кадры называются `<prefix>-001.png`,
  `<prefix>-002.png`, …

## Порядок загрузки

1. `depends_on` (жёстко) → 2. `load_after` (если мод есть) → 3. `priority`
(больше — позже) → 4. `id` по алфавиту.

Правило одно и то же везде: **что применено позже, то и главнее**. В панели
модов ниже в списке = позже.

## Новые типы контента (`into: "rule"`)

Раньше часть контента была зашита в код. Теперь это правила в
`assets/config/content_rules.json`, и мод может их расширить.

| Ключ | Что это |
|---|---|
| `spells.spheres` | школы магии (`Fire`, `Water`, …). Книга одного заклинания продаётся в лавке сама; чтобы продавалась книга всей школы (`Book <Сфера>`), добавь её предметом с `quality: "Book"` и ценой > 0 |
| `items.weapon_types` | что считается оружием |
| `items.shield_types` | щиты |
| `items.sword_types` / `club_types` / `two_handed_types` | стиль удара и двуручность |
| `items.head_types` / `cloak_types` / `body_types` / `hands_types` / `feet_types` / `amulet_types` / `ring_types` | слоты экипировки |
| `units.hostile_palette` | палитра, по которой набор считается враждебным |
| `units.loot_families` | семейства лута |
| `units.loot_by_species` | вид зверя → семейство (запасное правило, если у набора нет `loot_family`) |
| `spawn.gray_species` | **какие звери вообще встречаются в мире** (по видам) |
| `races` | расы на экране героя: `{id, label, two_styles}` |
| `map.house_folders` / `map.decor_folders` | жильё и декор города по расе |
| `map.city_props` | id пропов вокруг города |
| `inn.candidates` | наборы наёмников в таверне, от слабого к сильному |

```json
[
  {"into": "rule", "op": "append", "key": "spells.spheres", "value": ["Shadow"]},
  {"into": "rule", "op": "append", "key": "items.head_types", "value": ["Crown"]},
  {"into": "rule", "op": "append", "key": "spawn.gray_species", "value": ["scourge"]}
]
```

После этого предмет с `"type": "Crown"` встаёт в слот шлема, `Book Shadow`
становится книгой новой школы, а зверь `monsters/scourge` начинает попадаться
в мире. Портрет расы ищется по конвенции `<раса>_<пол>_<роль>.png`; флаг
`two_styles: true` включает второй стиль (так сделаны люди).

**Тиры Серых.** Для вида `<вид>` генератор берёт наборы `monsters/<вид>` (тир 1)
и `monsters/<вид>_t2..t5`. Если у мода есть только тир 1, остальные просто
не попадут в пул спавна — ошибки не будет.

## Панель модов

Главное меню → **«Моды и дополнения»**:

- превью (`thumb.png`; без него — первая буква имени), имя, версия, автор;
- переключатель включения;
- порядок: `▲` / `▼`, **ниже в списке = применяется позже**;
- ошибки и предупреждения мода — под его строкой;
- «Открыть папку» — проводник на `user://mods`;
- «Обновить» — пересканировать папку без перезапуска.

Настройки (что выключено и ручной порядок) лежат в `user://mods.cfg`, а **не** в
сейве: набор модов — свойство установки, а не сохранения.

⚠️ Включение, выключение и порядок применяются **после перезапуска игры**:
данные баз разбираются один раз при старте.

## Профиль модов в сейве

В сейв пишется `mods: [{id, version, priority}]` — что было включено на момент
сохранения. При загрузке:

- мод пропал или выключен → **предупреждение в лог**, мир грузится;
- версия другая → предупреждение с обеими версиями.

Игра не отказывается открывать мир (в отличие от Space Engineers, где удаление
мода ломает сохранение): предметы не исчезают из сейва, но найдутся не все.

## Где увидеть свой контент в игре

Лавка торгует **не всем**. Это важно знать до того, как искать свой предмет:

| Что добавил | Где искать |
|---|---|
| Заклинание | книга-свиток этого заклинания появляется в лавке («Книги и свитки») сама |
| Книга школы (`quality: "Book"`, цена > 0) | там же; открывает всю школу |
| Зелье (`quality: "Potion"`, цена > 0) | лавка, вкладка «Зелья» |
| Рецепт (`quality: "Recipe"`, `bp`) | лавка, вкладки рецептов |
| Оружие и броня | **в лавке не продаются** — падают с врагов (целыми или сломанными) |
| Монстр | в мире, если его вид добавлен в `spawn.gray_species` |
| Здание | палитра редактора карт (по id) |

Экипировка с врагов: обычный поток — сломанные вещи (чинятся в мастерской),
редкий бонус и боссы — целые. Модовый предмет с `price` в пределах бюджета
врага может выпасть целым.

**Про стычки.** Монстры в мире дерутся и между собой (динамические стычки
19.10): если зверь умер «сам», скорее всего рядом прошла стычка, которую игра
доразрешила, когда ты подошёл. Это не поломка мода.

## Диагностика

Все ошибки собираются в `ModLoader.errors()`, предупреждения — в
`ModLoader.warnings()`. Принципы:

- **конфликт ключей** — ошибка с указанием, кто занял ключ;
- **два мода правят один ключ** — предупреждение, применяется последний;
- **битый JSON** — ошибка, мод пропускается, игра стартует;
- **потерянный ассет** — ошибка, запись пропускается.

Ничего из этого не роняет игру: базовая версия остаётся рабочей.

### Проверка мода без игры

```powershell
godot --headless --path . --script res://tests/mod_validate.gd -- C:/путь/к/папке/мода
```

Без аргумента проверит все моды в `user://mods` и `res://mods`. Что ловит:
битый JSON, отсутствие `id`, `id` ≠ имя папки, неизвестные `into`/`op`,
`add` на занятый ключ, `patch`/`append`/`remove` по несуществующему ключу,
`extends` в никуда, отсутствующие файлы `mod://…` и `res://…`.

## Примеры

| Пример | Что показывает |
|---|---|
| `docs/mods/examples/starter/` | Минимальный шаблон: одна запись, с которой начинают |
| `docs/mods/examples/warden/` | Зверь на базе волка, его клык, патч обычного волка |
| `docs/mods/examples/scourge/` | Полный набор: новая школа магии, новый тип шлема, заклинание, предметы, зверь в спавне |

Скопируй папку в `user://mods/` — и мод загрузится.

## Чего пока НЕТ

- **зданий со своим артом**: арт структур грузится только из
  `res://assets/structures/<папка>/`; мод может менять параметры существующих
  зданий (`patch` по id), но не принести новую графику здания;
- фракций и «мировых» рас в SIM-слое: новая раса в `races` работает на экране
  героя и в генераторе (жильё/декор), но в политике мира её нет;
- скриптовой логики в модах — только данные;
- замены предмета из выключенного мода на видимый плейсхолдер в сумке
  (сейчас он просто не находится, сейв при этом не портится);
- новых ролей/пресетов героя (`PRESETS` — статы, а не контент-данные).
