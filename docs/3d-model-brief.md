# 3D-модель персонажа → спрайты игры

Бриф для моделлера. Игра двумерная: у героя — **12 кадров 64×64**, вид три
четверти с востока + зеркало (`idle 1 + move 4 + attack 3 + die 4`). Мы делаем
модель в 3D и **рендерим** её в эти кадры сами: так один раз сделанная модель
даёт любое число ракурсов и поз.

Что это значит для тебя: **git не нужен**, ничего в репозиторий не коммитится.
Ты присылаешь файл модели и четыре анимации — дальше наша часть.

---

## 1. Что прислать

| Файл | Обязательно | Зачем |
|---|---|---|
| `<имя>.blend` | да | основной источник; текстуры упакованы (File → External Data → **Pack Resources**) |
| `<имя>.glb` | да | страховка на случай проблем с версией Blender |
| `<имя>_preview.mp4` | да | 5–10 с: четыре действия подряд, камера сбоку-спереди |
| ответ на два вопроса по правам | да | см. §7 |

**Blender 4.2 или 5.2** (у нас стоят обе). Присылай в Telegram **файлом**, не
как фото — фото пережимается и геометрия/текстуры портятся.

---

## 2. Четыре действия

Каждое — **отдельный Action**, имя строго латиницей, без пробелов и суффиксов.

| Действие | Action | Длина @24fps | Требование |
|---|---|---|---|
| стоит | `idle` | 24–48 кадров | стойка на месте, лёгкое дыхание |
| идёт | `walk` | 24 кадра = 1 цикл | **первый кадр = последний позой** (зацикливается), ноги не скользят |
| бьётся | `attack` | 18–24 кадра | замах → удар → возврат в стойку |
| умирает | `die` | 24–36 кадров | падение; **последний кадр — лежит на земле** |

Из каждого действия мы берём фиксированное число кадров (1/4/3/4), поэтому
важна не длина, а чтобы позы шли по нарастающей и цикл `walk` был ровным.

---

## 3. Ориентация, масштаб, пивот

Это главное, из-за чего файлы возвращают на переделку.

- Blender **Z-up**, персонаж смотрит в **−Y** (в Blender это вид «спереди»,
  Numpad 1).
- **Ступни на уровне Z = 0**, пивот — между ступнями в начале координат
  (X = 0, Y = 0).
- Рост **1.7–1.9 м**, 1 unit = 1 метр.
- `walk` — **ходьба на месте**, без root motion: за цикл персонаж не смещается
  по X/Y.
- `die` — тело остаётся рядом с пивотом, не уезжает на несколько метров в
  сторону: кадр всего 64×64, тело в двух метрах от ног в него не влезет.

---

## 4. Технические требования

- Анимация **запечена**: Object → Animation → Bake Action (или ключи на каждой
  кости). Живые IK/constraint'ы при экспорте ломаются — на рендере получится
  «замороженная» поза.
- **Action'ы должны пережить сохранение.** Если Action не назначен объекту, при
  сохранении Blender его выбрасывает, и файл приезжает вообще без анимаций
  (проверено на тестовой модели). Включи у каждого Action «щит» (Fake User) или
  положи их полосами в NLA — тогда они останутся в файле.
- Если делаешь `.glb`, экспорт → Animation mode: **Actions** (или сначала
  разложи действия в NLA-полосы). Иначе в `.glb` не будет ни одной анимации,
  хотя в `.blend` всё на месте.
- В сцене только персонаж: **без камеры, света, пола, сетки, фона**.
- Один материал, текстуры ≤ 1024², стиль плоский: без глянца, металла,
  прозрачности и эмиссии. Мы рендерим в 64 px — детали мельче 2–3 px пропадут.
- Скиннинг: одна арматура, веса без «дыр» (иначе в кадрах будут разрывы).
- Нормали наружу, без инвертированных граней; полигонаж до ~30–50k
  треугольников — больше для 64 px не нужно.

## 5. Чего делать НЕ надо

- Не рендерить спрайты самому и не подгонять камеру — угол, свет и масштаб у
  нас фиксированы (§8), иначе кадры не совпадут со всей игрой.
- Не красить в палитру игры и не рисовать контур — это пост-обработка.
- Не делать восемь ракурсов: первый заход — один ракурс + зеркало.

## 8. Что делаем мы (для понимания, не для повторения)

- Рендер 12 кадров **64×64** с ортокамеры: азимут −60°, возвышение 20°, свет
  сверху-слева, прозрачный фон, рендер в 4× и одно понижение до 64 px.
- Фигура в кадре — **54 px** из 64, пивот в ногах **(32, 62)**; масштаб
  считается один раз по `idle`, чтобы персонаж не «дышал» размером между
  кадрами.
- Кадры кладутся в `assets/units/hero/<имя>/sprites-001..012.png`, рядом
  `_entry.json`, строка в `assets/units/units_db.json`.
- Опционально — 1 px тёмный контур (`--outline`), чтобы 3D-рендер ближе читался
  к рисованным спрайтам.
- Скрипт сам предупреждает, если поза вылезла за кадр (`WARN ... content touches
  the frame edge`) — это значит, что действие слишком широкое для 64×64.

Команда (запускаем мы, тебе повторять не нужно). Нужны Blender 4.2+ и Python с
Pillow; сам скрипт найдёт Blender сам:

```
python tests/render_3d_frames.py --blend <файл> --name <имя> --outline
```

## 9. Пилот: сначала только `idle`

Первый заход — **только стойка**. Остальные три действия пока не делай.

Причина простая: наши спрайты — рисованный пиксель-арт с контуром, а
3D-рендер даже с плоским светом читается иначе. Дешевле поймать расхождение на
одном кадре, чем после недели работы над всеми анимациями. Мы рендерим один
кадр, ставим рядом с текущим героем в игре и присылаем сравнение.

Если стиль совпал — доделываешь `walk`, `attack`, `die` в том же файле.
