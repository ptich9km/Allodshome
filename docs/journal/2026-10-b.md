# Журнал сессий — октябрь 2026, 11.10+ (архив из AGENTS.md §12)

### 28.10 (позже) — щит не перекастовывается, кулдаун от познания магии

Ветка `feature/agent-magic-pause`. **Автотесты зелёные, в игре НЕ ПРОВЕРЕНО.**
Жалоба игрока: «маг кастует щит постоянно; кулдаун должен считаться от познания
магии и навыков, а не как повторное применение заклинания».

**Причина перекаста — не в кулдауне.** Щит героя хранится в статусах как
`shield_armor` (временная броня), а не как `shield`; у врагов — в meta
`shield_strength/shield_time`. Автокаст проверял `has_effect(u, "shield")` —
всегда false, поэтому щит накладывался заново каждый кулдаун. Заведён
`StatusEffects.is_active(unit, type, sphere)`, который для `shield` смотрит
`shield_armor_time()` и absorb-meta; им пользуются и уровни баффов, и автокаст
свитка.

**Кулдаун от навыка.** Было: `cast_cooldowns[name] = SpellDB.cooldown_of(name)`,
то есть плоская база из `spells_db`. Стало —
`Game.spell_cooldown(caster, spell, power_override := -1)`:
`base × (1 − 0.5 × clamp(SP,0,100)/100)`, где `SP = навык сферы + разум − sp_offset`
(та же формула, что у урона), минимум **0.5 с**. Пример: Щит (база 10 с) —
9.10 с при навыке сферы 20 и разуме 13, 5.10 с при навыке 100.

**Свитки — кулдаун МАГИИ ВНУТРИ свитка.** Отдельного «кулдауна применения
предмета» нет; сила свитка (50 обычный / 100 эльфийский) подставляется как
познание: 50 → 75 % базы, 100 → 50 % базы. Проверено, что это работает на всех
путях:
* автокаст свитка (`_tick_auto_scroll`) — ставит и проверяет расчётный кулдаун;
* ручной свиток (ЛКМ/хоткей/из склада) — **раньше кулдаун не ставился вообще**,
  теперь `apply_scroll_to_target/_point` его ставят;
* кольцо-таймер в книге для свитка считает ту же величину с силой свитка,
  иначе визуал врал бы (показывал 10 с вместо 7.5).
У мага авто-лечение и баффы идут через `cast_spell` → `can_cast` (кулдаун) →
`_commit_cast` (ставит расчётный).

Применено в `_commit_cast`, в автокасте свитка и в интерфейсе (подсказка
«Кулдаун: …» и кольцо-таймер считают ту же величину).

**Тесты:** `auto_magic_smoke` +3 (щит наложен; щит не перекастовывается при
живом `shield_armor`; кулдаун падает с навыком 5.10 < 9.10 < 10.00);
`scroll_book_smoke` +5 (кулдаун свитка 7.50 < 5.00… то есть 100 < 50 < база;
75 %/50 % базы; ручной каст ставит кулдаун и он равен расчётному).
Регрессии: `magic_smoke`, `package_c_smoke`, `scroll_book_smoke`,
`spell_vfx_smoke`, `magic_pause_smoke`, `settings_smoke`, `inventory_ui_smoke`,
`shop_ui_smoke`, `equipment_combat_smoke`, `runtime_errors_smoke` — зелёные,
парсинг чистый.

**Требуется ручная проверка:** маг с включённым авто-волшебством — щит ставится
один раз и держится 60 с; у прокачанного мага заклинания готовы заметно быстрее.

### 28.10 — свитки воина в книге, единственный автокаст, эльфийские свитки

Ветка `feature/agent-magic-pause`. **Автотесты зелёные, в игре НЕ ПРОВЕРЕНО.**
Жалобы/требования игрока: «ускорение кастуется постоянно, не дождавшись конца
действия»; «у воина книга пустая — свитки должны попадать в неё»; «магу свитки в
книгу не надо»; «10 свитков нельзя сжигать за секунду»; «эльфийские свитки должны
быть заметны и сильнее».

**1. Перекаст ускорения (баг).** Проверка «эффект уже висит» брала сферу
ЗАКЛИНАНИЯ (`Astral`), а у `Haste/Bless/Shield/Invisibility` в эффекте поля
`sphere` нет — запись хранится с `""`, сравнение не совпадало НИКОГДА, и маг
перекастовывал ускорение каждые 10 с при длительности 20 с. Теперь сфера берётся
из самого эффекта.

**2. Книга воина = свитки из склада.** `refresh_spell_book` для героя без маны
строит ячейки из склада (одна на тип, со счётчиком), склад остаётся источником
правды — свиток можно продать. Ячейка: ЛКМ — прицеливание/каст, ПКМ — пометка
единственного автокаста, Ctrl+1..9 — хоткей. **Маг свитки в книгу не берёт**
(они бы затирали книжную магию) — закреплено тестом.

**3. Единственный автокаст.** ПКМ помечает ОДИН свиток; помечать можно только
«на себя» (лечение/бафф/self) — боевой свиток отвечает «автокаст только на себя».
Каст: только на себя, не чаще кулдауна заклинания, для баффа — пока эффекта нет,
для лечения — при HP ниже 45 %, ровно один свиток за каст. Уровни
«Базовое/Среднее/Максимальное» — **только для мага и только для изученных
заклинаний** (`charges == -1`); свитки уровнями не тратятся, воин не «замена магу».
Тест: 10 свитков + серия кастов → израсходован ровно 1.

**4. Эльфийские свитки.** В базе уже были два класса: `Scroll` (`castSpell=X:50`)
и `SuperScroll` (`:100`), но сила не использовалась вовсе, а имя было
техническим. Теперь:
* `SpellDB.scroll_power_of(item)` читает силу из `effects` (правка: раньше ждала
  три части через `:` и всегда получала -1);
* `Game.spell_damage(..., power_override)` — сила свитка заменяет навык героя
  при расчёте УРОНА (баффы и лечение не масштабируются — решение игрока);
* имена: «Свиток: …» и «Эльфийский свиток: …» (58 позиций, из spells_db `ru`);
* `CraftVFX.apply_elven()` — мягкое сине-фиолетовое свечение и 4 мерцающие
  звёздочки поверх иконки (шейдер на TIME, без обновления из кода), в магазине,
  складе и книге. Для не-эльфийских материал снимается, иначе свечение
  оставалось бы на переиспользованной иконке.

**Тесты:** новый `scroll_book_smoke` (17): книга воина из склада, три типа = три
ячейки, мага не трогает, ПКМ только для «на себя», сила 50/100 и реальный урон,
имена, свечение; `auto_magic_smoke` +4 (ускорение не перекастовывается; у воина
уровни ничего не кастуют; из 10 свитков сгорает 1; после снятия эффекта — снова).
Регрессии: `magic_smoke`, `package_c_smoke`, `shop_ui_smoke`,
`inventory_ui_smoke`, `spell_vfx_smoke`, `magic_pause_smoke`, `settings_smoke`
58/0, `runtime_errors_smoke` — зелёные, парсинг чистый.

**Требуется ручная проверка:** купить воину свитки → они в книге; ПКМ по свитку →
«A» и каст по кулдауну на себя; 10 свитков не сгорают; эльфийские заметны в
магазине/складе/книге; у мага ускорение больше не перекастовывается.

### 27.10 (позже) — авто-волшебство в настройках, нимб благословения, лечение НПЦ

Ветка `feature/agent-magic-pause`. **Автотесты зелёные, в игре НЕ ПРОВЕРЕНО.**
Жалобы игрока: «щит велик», «не вижу благословения», «нет в меню магии настройки
авто-волшебства», «героя подбили — он не лечится и никого не лечит».

**Что оказалось в коде.** Авто-баффы (`auto_buff_tier`) и цели уже были, но:
переключались только скрытым **Alt+ПКМ по книге**; `auto_buff_targets="party"`
перебирал `Game.party` (наёмники), а **сам маг в него не входит**; авто-лечение
включалось ТОЛЬКО после ручного ПКМ-назначения (`Game.auto_spell == "Heal"`),
поэтому по умолчанию не работало. У Bless не было постоянной ауры: в
`_attach_auras` были только shield/resist/haste.

**Сделано:**
* **Щит −25 %**: `SHIELD_PX` 20×26 → 15×20.
* **Аура благословения** (`aura_bless`): маленький тёплый нимб с шестью лучами
  над макушкой (16 px, аддитивный, пульс). Подключается по типу эффекта `bless`,
  исчезает по `StatusEffects.has_effect(unit,"bless")`, стоит выше макушки и
  ниже шкалы HP (шкалу поднял с 6 до 16 px над головой, чтобы не перекрывала).
* **Esc → Настройки → «Магия»** (четвёртая вкладка, `_choice_row`):
  уровень **Базовое (по умолчанию) / Среднее / Максимальное** и цель
  **Только я (негуманно) / Я и моя группа (по умолчанию) / Я, группа и нейтраллы**.
  Наборы: базовое — ускорение+щит; среднее — +благословение и 4 защиты;
  максимальное — +невидимость. В сейв НЕ пишется.
* **Авто-лечение** стало частью авто-волшебства: раз в секунду, порог
  `auto_heal_ratio=0.45`, заклинание — ручной `auto_spell` или первое изученное
  лечения; мана/кулдаун через `can_cast`. Цель — тот же переключатель.
* **Маги-НПЦ лечат** себя и раненых союзников рядом (герой, стража, жители,
  наёмники; врагов — никогда): кулдаун `npc_heal_cooldown=6 c`,
  сила `npc_heal_percent=0.12` от максимума, радиус `Heal` (200 px), визуал —
  `heal_cross` и звук `magic.heal`. Ключи добавлены в `game.cfg [magic]` и в
  `GameConfig.DEFAULTS`.
* Скрытый Alt+ПКМ оставлен как быстрый цикл уровня; подпись в книге теперь
  «Авто-волшебство: …» и обновляется при смене настроек.

**Тесты:** `package_c_smoke` переписан (24 проверки: уровни, цели, маг в списке,
выбор лечения без auto_spell); новый `auto_magic_smoke` (6: самолечение без
ручного назначения, бафф себя, «только я» не лечит союзника, «я и группа» лечит
наёмника, НПЦ-маг лечит героя); новый `npc_mage_heal_smoke` (8: себя, союзника,
кулдаун, далёкого, воина, врага); `settings_smoke` 58/0 (4 вкладки, нажатия
меняют статики Game); `spell_vfx_smoke` +5 (нимб bless, исчезновение).

**До-существующий провал, НЕ из этого пакета:** `game_config_smoke` «эталон vs
DEFAULTS» — 5 ключей расходились ещё на HEAD (`combat.enemy_attack_dmg_div`,
`npc.guard_aggro_radius`, `npc.guard_leash`, `zone.start.gray_damage_min/max`).
Новые ключи `npc_heal_*` в файле и в DEFAULTS согласованы.

**Требуется ручная проверка:** нимб благословения над головой; уменьшенный щит;
Esc → Настройки → «Магия»; маг сам лечится после боя; НПЦ-маги лечат друг друга.

### 27.10 — метрики фигуры: бой вплотную и аура у головы, а не у живота

Ветка `feature/agent-magic-pause`. **Автотесты зелёные, в игре НЕ ПРОВЕРЕНО.**
Жалоба игрока: «персонаж бьётся в трёх шагах от монстра; магия огня, которая
должна быть у головы, — у живота». Оба симптома — одна арифметика.

**Кадр ≠ фигура.** Все кадры — холст 64×64, а фигура внутри ~20×54
(замер по альфе: `y 8..61`, ноги на 2–3 px выше низа холста).
`UnitAnim.visual_height()` возвращал высоту ХОЛСТА, поэтому «центр корпуса»
`0.45×64 = 28.8` попадал в живот 54-пиксельной фигуры, а аура огня считалась
от той же неверной высоты.

**Хит-бокс был 96×96 со сдвигом.** `units_db.json`: у всех наборов `w=h=64` и
`sel_box` НЕ ЗАДАН, а `UnitDB.sel_box()` на отсутствие отдаёт заглушку
`Rect2i(16,16,96,96)`. Проверка «это дефолт» срабатывала только при `w>=128`,
то есть никогда; бокс собирался как `position + (-32,-64) + (16,16)` — от −16
до +80 по X. `Game.units_range` мерил расстояние между такими боксами, и бой
начинался «в трёх шагах» (при `ATTACK_RANGE = 40`).

**Сделано:**
* `Game.texture_content_rect(tex)` — рамка непрозрачных пикселей кадра с кэшем
  по пути ресурса (порог альфы 0.06, чтобы ореол не растягивал рамку).
* `UnitAnim.content_rect()` (текущий кадр) и `body_rect()` (кадр СТОЙКИ —
  чтобы меч/посох в кадре удара не раздували тело), с учётом масштаба и зеркала.
  В `UnitAnimBase` — пустые заглушки, `RiggedAnim` живёт на своей высоте.
* `Game.unit_local_rect()` (ноги ≈ 0, макушка −y), `unit_visual_height()` →
  высота фигуры (54), `unit_body_rect()`, `unit_hit_rect()` → тело (20×54).
  Явный `sel_box` берётся только если он реально лежит внутри кадра.
* Дистанция боя: `Game.attack_reach(u)` вместо константы 40. Длина по оружию:
  палица 8, меч/топор 10, посох 14, копьё 20, у монстров 10. Выход из боя —
  `reach + 8` (удар — `reach + 12`). Обновлены герой, враг, наёмник (у него
  было 40 от ЦЕНТРА) и страж НПЦ (было 30).
* **Подъём узла анимации (рельеф).** `UnitAnim.position.y = -рельеф`, то есть
  фигура нарисована на 20–25 px ВЫШЕ точки на земле, а ауры стояли ровно в
  точке `unit.global_position`. Из-за этого все обручи (и «ветер ускорения»)
  оказывались ниже ног — вторая жалоба игрока со скриншотом. Теперь `SpellAura`
  добавляет `_anim_offset()` к позиции спрайта, крест лечения ставится по
  макушке фигуры с тем же подъёмом, а шкала HP — по `top - h - 6` (первая
  попытка с перевёрнутым знаком увела её ПОД ноги, поймано по скриншоту).
* Нижние ряды подняты: земля 0.20, воздух 0.40, вода 0.64, огонь 0.88 высоты
  фигуры; высота обруча 18 px — низ обруча земли на 3.8 px ВЫШЕ подошв
  (проверяется тестом), ветер ускорения — на 4 px.
* Шкала HP у героя и врага вешается от макушки ФИГУРЫ, а не холста.
* Ауры защит: `RESIST_ROW_FRAC` — доли высоты фигуры от ног (земля 0.10,
  воздух 0.36, вода 0.62, огонь 0.88), обруч тонкий (высота 20 px, ширина =
  ширина тела + 20), щит — на 0.55 высоты. Замер: огонь на 49.5 из 54 px,
  земля на 7.4.

**Замеры на герое (`hero/war_men`):** фигура 20×54 при холсте 64; бокс 20×54
по центру; зазор между телами на соседней клетке 12 px, через клетку 44,
«три шага» 76 (старый бокс 96 давал 0 — то есть бой начинался).

**Тест `tests/unit_figure_metrics_smoke.gd` (25 проверок, OK):** фигура ниже и
уже холста, ноги у основания, `unit_visual_height` = фигура, бокс уже клетки и
по центру, кадр удара не раздувает бокс, дистанции 32/64/96 px, длины оружия
по возрастанию, огонь ≥ 0.78 высоты, земля ≤ 0.30 и её низ НЕ под подошвами,
обруч поднимается вместе с фигурой (рельеф). Регрессии:
`spell_vfx_smoke`, `unit_physics_smoke`, `hover_pixel_smoke`, `package_a_smoke`,
`npc_spawn_smoke`, `events_smoke`, `equipment_combat_smoke`, `magic_pause_smoke`,
`anim_contract_smoke`, `zone_travel_smoke`, `save_menu_smoke`,
`runtime_errors_smoke` — зелёные.

**Осталось в пакете (по решению игрока):** защиты — тоньше, альфа выше,
штрихов 5–7 (сделано); наземные эффекты (стена огня по клеткам, камни, яд,
метель, ориентация стен, убрать «сетку») — следующий шаг.

**Требуется ручная проверка:** подойти к монстру — удар должен начинаться
вплотную; копьё/посох бьют дальше меча; шкала HP над головой; аура огня у
головы.

### 26.10 (позже) — защиты-ветерок и летающий щит: шейдер аур не применялся вовсе

Ветка `feature/agent-magic-pause`. **Автотесты зелёные, в игре НЕ ПРОВЕРЕНО.**
Пакет B из плана правки магии (жест игрока: «многие спецэффекты однотипные —
точка плавает туда-сюда»).

**Главная причина оказалась не в размере, а в компиляции.** `_zone_shader_with_mode()`
подставлял `render_mode blend_add, unshaded;` **перед** `shader_type canvas_item;`,
а такой шейдер не применяется вообще — материал рисовал сырую белую текстуру 4×4.
Поэтому ВСЕ ауры и осколки метели всегда были белыми квадратиками: при scale 0.45
это была «точка», после перевода размеров в пиксели — «белый квадрат на всю
фигуру». Теперь `render_mode` вставляется ПОСЛЕ объявления типа (поиском подстроки,
а не по `begins_with("\n")`: файл с CRLF ломал сравнение и давал ДВА `shader_type`).

**Размер в пикселях, а не множителем.** `white_texture()` — 4×4 px, а аура задавала
`scale` 0.45…1.6, то есть 1.8–6.4 px. Заведены `SpellVFX.fit_px(sprite, w_px, h_px)`
и `sprite_px()`. Крест лечения — 22 px (было 2.2), ветер ускорения — 40×12 px.

**Защита от стихии — бегущие штрихи по обручу вокруг корпуса** (`aura_breeze`),
а не точка и не «пузырь». Обруч узкий (0.78–0.90 радиуса), штрихи бегут по кругу,
число и скорость зависят от `uniform school`, цвет — от школы. Обруч рисуется
ПОЗАДИ юнита (`show_behind_parent`): всё, что упирается в силуэт, скрывается
спрайтом, наружу выходят только струи по бокам — иначе полосы шли поперёк лица.

**Четыре школы не сливаются в одно пятно** по трём признакам сразу:
* **высота ряда**: земля у ног, воздух у бёдер, вода у груди, огонь у головы
  (`RESIST_ROW_RANK`, шаг 14 px; пересчёт «столбика» по порядку наложения удалён);
* **цвет, разведённый по соседям**: воздух стал бледно-жёлтым, земля —
  оливково-серой (прежние «светло-голубой» и «светло-коричневый» путались с водой
  и огнём);
* **движение**: число штрихов и скорость зависят от школы, у огня ярче вверх,
  у земли — вниз;

### 26.10 — магия перестала работать на тактической паузе

Ветка `feature/agent-magic-pause`. **Автотесты зелёные, в игре НЕ ПРОВЕРЕНО.**
Пакет A из плана правки магии (дальше: B — защиты/щит, C — наземные зоны).

**Корень бага оказался шире магии.** `game.gd:733` ставит корню сцены
`PROCESS_MODE_ALWAYS` (нужно для Esc-меню и `_input`), а все дети наследовали это
через `INHERIT`. То есть `get_tree().paused = true` не останавливал НИЧЕГО:
пауза держалась только ручными проверками `Game.is_paused` у героя, врага, НПЦ,
наёмника и `Game._process`. У магии таких проверок не было вовсе — зона жила и
тикала урон, снаряд долетал и бил, аура следила за юнитом, твины вспышек/света
играли, `Game._input` на паузе запускал прицеливание и каст.

**Решение — не снимать ALWAYS с корня** (на нём меню и ввод), а сделать
паузабельными конкретные узлы мира: `PROCESS_MODE_PAUSABLE` у `Projectile`,
`SpellZone`, `SpellAura` и у эмиттеров `GPUParticles2D` (частицы симулируются
движком, без `_process`, и наследовали Always). Твинам — `TWEEN_PAUSE_STOP`
через новый `SpellVFX.world_tween()`: режим по умолчанию `BOUND` привязан к
узлу-владельцу, а владелец — Always-корень, поэтому твин паузу не замечал.
Таймер авто-освобождения частиц: `create_timer(delay, false, ...)`.

**Ввод.** `Game._input` при паузе пропускает только Space (снять паузу) и Esc
(меню); клики по миру, хоткеи 1..9 и решение прицела не проходят. Плюс
страховки в `Game.handle_click`, `Game._resolve_spell_click`,
`Player.cast_spell`, `ui._quick_cast` и `ui._cast_spell_button`.

**Прыжок времени шейдера.** `SpellZone` брал время для шейдеров из
`Time.get_ticks_msec()` — реальные часы. После паузы пламя/контур прыгали вперёд
на всю её длительность. Теперь накопленный `_elapsed` (как уже было у ауры и
снаряда).

**Тест `tests/magic_pause_smoke.gd` (26 проверок, OK):** зона не теряет жизнь,
не копит тик урона и не идёт по времени шейдера; снаряд не двигается и летит
после; аура не покачивается; `cast_spell` отказывает без траты маны и кулдауна;
хоткей не входит в прицеливание; твин замирает; частицы паузабельны; Space
снимает паузу. Регрессии: `spell_vfx_smoke`, `fire_wall_smoke`,
`spell_mechanics_smoke`, `lighting_smoke`, `save_menu_smoke`, `zone_travel_smoke`,
`runtime_errors_smoke` — зелёные, парсинг без SCRIPT ERROR.

**Требуется ручная проверка:** Space на живой игре с активной стеной огня,
летящим снарядом и висящей защитой — всё обязано замереть и продолжиться без
скачка пламени.

### 23.10 — загрузка слота другого героя: живой Player, без дубля спрайта, миникарта

Жалобы игрока подряд после фикса папок сохранений: (1) загрузил слот мага,
а бегает спрайт воина и нет маны; (2) после фикса воин стоит, а поверх него
маг; (3) миникарта осталась от прежней игры и не показывает, где герой ходит.

**Причина (1).** `_restart_scene` подменяет карту на месте (`_swap_map`), сцена
и узел `Player` переживают загрузку. `SaveSystem.apply_payload` менял только
`Game.*` и поля склада — класс/пол/раса/портрет и спрайт оставались прежними.
Раньше это маскировал `change_scene`, убранный 22.10.

**Решение (1).**
- `Player._apply_hero_save` разделён на `_restore_from_hero_save` (голова/склад/
  экипировка/опыт/навыки) и `_apply_hero_save`; новый `reload_hero_state()`
  перечитывает класс-зависимое состояние на ЖИВОМ узле: `has_mana` по классу,
  max_hp/max_mana/current_*, скорость, спрайт (`anim_set_name()` уже учитывает
  класс/пол/расу), полоса HP/маны, набор анимации.
- `game.gd::_restart_scene` зовёт `reload_hero_state()` ДО `_swap_map`: карта и
  город спавнятся уже с расой нового героя.
- `game.gd::_refresh_ui_after_hero_swap()` после подмены карты: закрывает
  открытые панели (`GameUI.close_all_panels`), перестраивает книгу магии,
  золото HUD, нижнюю панель, склад.
- `InventoryPanel.portrait_path()` — кукла берёт портрет текущего героя.
- Снаряжение чужого класса из старых сейвов не снимается, а пишется в лог.

**Причина (2).** `_ensure_sprite` снимала старый бэкенд только через
`queue_free()`; узел с именем `UnitAnim` уходит из дерева в конце кадра, и
новый `UnitAnim` (маг) добавлялся рядом со старым (воин) — два спрайта, воин
под магом.

**Решение (2).** `_ensure_sprite` отцепляет от родителя все дочерние
`UnitAnimBase` через `remove_child` и только потом `queue_free`.

**Причина (3).** `GameUI.alm_map` и кэш террейна `_minimap_base` жили дольше
одной карты: `_swap_map` создаёт новый узел `Map`, а кэш пересобирался лишь
при смене размера картинки (165×165 — тот же). Точка героя рисовалась по новым
координатам поверх старого биома.

**Решение (3).** `GameUI.rebind_map()` (сброс `alm_map` из группы, кэшей
террейна/тумана и таймера) вызывается сразу после создания узла `Map` в
`_swap_map` и в `_refresh_ui_after_hero_swap`; кэш привязан к
`get_instance_id()` карты, поэтому подмена узла пересобирает базу даже при
том же размере.

**Попутно.** `SCRIPT ERROR: has_method in base 'Nil'` из лога теста — это

### 22.10 — слот сохранения = своя папка: герой, карта, прогресс

Жалоба игрока: «каждое сохранение — своя папка в каталоге save; внутри
каждого сохранения карта, персонаж и процесс; при Save перезаписывается каждый
элемент папки; при удалении сохранения папка становится чистой».

**Формат.** `user://saves/<слот>/` содержит три элемента и файлы мира:
`hero.json` (герой, экипировка, склад, позиция), `map.json` (зона, сид,
туман, имя/путь карты) рядом с самой картой (`.alm` + sidecar-ы), и
`process.json` (мир SIM, события, квесты, метаданные слота). Карта копируется
байт-в-байт, поэтому после перезапуска это та же карта, а не новая по сиду.
Каждый элемент пишется атомарно (`.tmp` → flush → прежний в `.bak` → rename).
Удаление слота: файлы мира, `.bak` и снимок убираются, три элемента остаются
пустыми — папка на месте («становится чистой»).

**Снимок прежнего сохранения.** `previous.json` кладётся ДО перезаписи и
держит `{version, meta, data: {hero, map, world, events, quests}}` — целое
предыдущее сохранение. Поэлементные `.bak` держат лишь прежние версии
отдельных файлов, и мир в них разорван по трём элементам. Если элементы слота
сломаны без `.bak`, `load_slot()` восстанавливает слот из `previous.json`
(регрессия, которую поймал `save_smoke`: «битый файл без .bak → corrupt»).

**Загрузка.** `load_slot()` отдаёт ту же сводку v1 (`data.hero/map/world/
events/quests`), поэтому весь вызывающий код не изменился. Данные элементов
проходят `JsonSafe.decode` — без него позиция героя приезжала словарём
`{"__t": "v2"}`, и герой вставал на спавн (регрессия, которую поймали
`save_smoke`/`save_menu_smoke`).

**Перезапуск из слота — горячая замена карты, а не `change_scene_to_file`.**
Корутина старой сцены при смене сцены гибла на первом кадре новой
(`data.tree is null`), и точка входа из сейва терялась. Теперь
`_restart_scene` поднимает мир в WorldBus и делает `_swap_map(map, zone, true)`:
карта берётся из папки слота, герой встаёт на сохранённую позицию (непроходима
клетка — ближайшая открытая вокруг через `_find_open_spot`, а не спавн).

**Зоны.** Слот копит карты всех посещённых зон под общим именем
(`map_<сид>_<зона>_<раса>`): при переходе через портал `travel_to_zone` кладёт
карту новой зоны в слот (`SaveSystem.store_zone_map`), а `_zone_map_path`
берёт карту нужной зоны оттуда (`restore_zone_map`). Без этого после
перезапуска возврат в старую зону рождал карту с нулевым состоянием мира.

**Грабли.** `_atomic_copy(src, dst)` при `src == dst` уводил файл в `.bak` и
не оставлял ничего — слот терял карту, когда она уже лежала в `user://maps/`.
Теперь копирование поверх себя — no-op. `Params` в `Parametic` и `_basename_of`
сравнивают имя карты честно: `String.begins_with` на длинной конкатенации
префикса даёт `true` для чужой зоны, поэтому зоны разбираются по `split("_")`
(сид + раса совпадают, зона — предпоследняя часть).

**Проверено:** новый `tests/save_folder_smoke.gd` (папка с hero/map/process +
`.alm`, загрузка возвращает золото, позицию и карту из слота, портал кладёт
карты обеих зон в слот); `save_smoke`, `save_menu_smoke`,

### 17.10 (позже 4) — суккуб: смерть на колени вместо «лежит плашмя», и набор без фазы удара

Ветка: `feature/agent-orc-woman-and-strip-tools`. **Код и тесты зелёные. В ИГРЕ НЕ ПРОВЕРЕНО.**
Потрачено **$0.18** (3 полосы `succubus_die` + 2 `attack`, которые в итоге выброшены).

#### Крылатое существо не влезает в полосу — это анатомия, а не раскладка

Прежний `ANIM_DIE["legs"]` требует «arms spreading out for balance», и при падении
крылья расправляются. Замеры ширины фигуры по полосам:

| полоса | ширина панелей |
|---|---|
| старая `die` | 467 → 640 → 666 → **725** (сумма 2498 + зазоры > 2528) |
| `die` после правок | 488 → 566 → 735 → 660 |

То есть четыре панели **не помещаются в ряд даже без зазоров**. Успешная фаза
полёта `glide` работала только потому, что крылья там описаны отдельной фразой.

**Решение игрока: смерть = оседает на колени**, не ложиться плашмя. Поза вертикальная
и узкая. Попытка **прошла с первой** — зазоры 87/114/70, поле 78 px, `ГОДЕН`.
Понадобился `ANIM_DIE["kneel"]`: тело остаётся вертикальным, крылья сложены, колени
на той же линии земли.

#### Удар: игрок решил не тратить

`attack` не хватал **9 px** в зазоре (панели 2 и 3 почти слипались) при четырёх
правильных фигурах в ряд. По решению игрока заход прекращён, полоса убрана в
`C:\Temp\opencode\succubus_dropped\` (не удалена).

`extract_monster_nb.py` требовал все четыре полосы, поэтому набор без атаки просто
не собирался. Сделано необязательной, с честной записью `attack: 0` в
`_entry.json` и пометкой `NO ATTACK ANIMATION` в описании.

**Проверено, что общий инструмент не пострадал:** `--dry-run` по всем 9 принятым
наборам — «все 12 кадров совпали бы **байт в байт**». `_block_offset` в
`unit_anim.gd` считает начало блока из числа фаз, а не из жёстких индексов, поэтому
сдвиг нумерации при 9 кадрах учитывается сам.

### 17.10 (позже) — тиры Серых: 5 тиров перекраской, и почему тир 2 нельзя было оставить охрой

Ветка: `feature/agent-orc-woman-and-strip-tools`. **Код и тесты зелёные. В ИГРЕ НЕ ПРОВЕРЕНО.**

Игрок: Серым нужно 4–5 тиров. Решение — перекраска, а не генерация: набор это
12 кадров = 4 полосы ≈ **$0.24 за вид**, перекраска стоит **$0** (ни одного вызова
API) и не может испортить форму. Полоса из 7 видов × 4 тира = 336 кадров за $0.

#### Решение игрока по цветам: тир 2 отличается НЕ тоном, а насыщенностью

Наивно казалось, что тир 2 = «охра» (25°). Замер это опроверг: у **четырёх видов
из семи** нативный тон почти совпадает с 25°, и тир 2 был неотличим от оригинала.

| вид | нативный тон | | вид | нативный тон |
|---|---|---|---|---|
| squirrel | 13.1° | | wolf | 18.1° |
| bee | 20.6° | | dino | 25.9° |
| bat | 326.2° | | dragon | 115.2° |
| ghost | 208.2° | | | |

Тон меряется **хрома-взвешенным** круговым средним (вес = насыщенность): у серых
пикселей HSV Hue не информативен, и обычное среднее по всем видимым пикселям даёт
числа, не совпадающие ни с чем.

Игрок выбрал: тир 2 различает **насыщенность и светлота** — `×1.55` к насыщенности
и `×0.72` к светлоте, тон остаётся 25°. Насыщенность в HSV не может сделать янтарный
янтарнее, а потемнение и подсыщение превращают рыжего волка в тёмного янтарного.

#### Баг, который стоил двух тиров: `2π/180` вместо `π/180`

Контактный лист показал, что тир 4 вышел **тем же оливковым**, что тир 2, а тир 3 —
бирюзовым вместо зелёного. Причина найдена пошаговым прогоном формулы, а не на глаз:

```python
target = target_deg * (2.0 * np.pi / 180.0)   # 25° -> 0.873 рад = 50°
target = target_deg * (np.pi / 180.0)         # 25° -> 0.436 рад = 25°
```

Удвоение объясняло ВСЕ четыре результата ровно: 25→50, 95→190, 205→50, 285→210.

**Поймано синтетикой, а не на реальном спрайте:** равномерный спрайт 30° при цели 25°
давал 47.8°. Проверка построена на известном тоне — это проверка инварианта функции,
а не агрегата вида «похоже на цель». Допуск = 2 шага сетки PIL H (360/256 = 1.406°,
итого 2.81°), фактическая ошибка ≤2.34°: вход и выход квантуются, спрайт 30°
физически не представим (PIL округляет до 29.53°).

#### Проверка светлоты — ОТНОШЕНИЕМ, а не «почти не изменилась»

Тир 2 затемняется намеренно, и вольный допуск «светлота почти сохранилась» пропустил
бы любую проваленную яркость. Проверяется `l1/l0` против заданного `val_mul`.
Чувствительность **доказана мутацией**: `val_mul = 1.00` и `0.50` дают ровно FAIL,
правильные `0.72` проходят (факт 0.714 — расхождение от квантования).

#### Часть 2. Три ошибки инструментов, все на размере ширины

**1. Фигуры считались колонками — это не работает в принципе.** У соседних

зверь вписывается по обеим осям: бегущий 62×28, стоящий 40×54.

### 15.10 — смерть героя проигрывалась заново: нечем было закончить блок

Ветка: `feature/rigged-units`. **Код и тесты зелёные. В ИГРЕ НЕ ПРОВЕРЕНО.**

Жалоба игрока: «когда я умираю мой персонаж постоянно проигрывает анимацию
смерти с нуля».

**Замер (не чтение кода).** Проба `tests/probe_death_anim.gd` убивала героя
напрямую и следила за `anim.anim_idx` по тикам. Два факта, которых не видно
из кода:

| | было | стало |
|---|---|---|
| `anim_idx` в момент паузы | **0** — первый кадр, герой стоит с распахнутыми руками | **3** — лежит |
| состояние | `dead` | `corpse` |
| после снятия паузы (Esc) | блок DYING играет **с нуля** | 120 тиков подряд `anim_idx = 3` |

**Причина: у героя не было шага «блок доигран — зафиксировать последний кадр».**
`advance()` на переходе через конец блока делает `anim_idx = 0` (замыкает цикл),
и `player.gd` сразу ставил `get_tree().paused = true`. Пауза спасала только до
первого Esc — после снятия паузы состояние всё ещё было `dead`, блок
проигрывался заново и снова ставил паузу. **Замкнутый круг.**

`enemy.gd` делает ровно это правильно: `freeze_last_frame(DYING)` + состояние
`"corpse"` (`enemy.gd:78-79`). У героя этого шага **не было никогда** — он
появился бы только на наборах с блоком DYING, а до 14.10 у героя стоял
чужой набор.

**Правка** (`player.gd`): после `advance() == true` — `freeze_last_frame(DYING)`
и `state = "corpse"`; добавлена ветка `"corpse"` в `_physics_process` (труп, без
физики); `corpse` добавлен в проверки `take_damage`, `heal_amount`,
`_tick_auto_cast` рядом с `dead`/`decay`.

**Тесты:** `war_men_smoke` 85/0 · `equipment_combat_smoke` OK · `spawn_smoke`
OK · `unit_physics_smoke` OK · `runtime_errors_smoke` — 0 ошибок в логе ·
`--quit` чистый. Пробы удалены после проверки.

#### Побочный замер: на карте разработчика Серых НЕТ вообще

Первая проба (та же сессия) печатает `Game.enemies = 0` при 67 спавненных
юнитах. То есть на `gen_smart_01.alm` (dev-карта из `main.tscn`) грей-пул

#### Две мои грабли в пробах этого вечера

2. **`print("a %d" + "b %s" % [x, y])`** — `%` связывается только со вторым

#### Часть 2. «Жердь» — три причины, и главная была в коде

### 13.10 — риг героя пересобран: 2 ракурса, настоящие руки, части больше не срезаны

**Переписано `tests/extract_rig_parts.py`:**

- суставы **измеряются по силуэту**, а не задаются долями: шея = минимум ширины, таз = максимум ширины корпуса, щиколотка = минимум над стопой;

- pivot задаётся **явно на каждый сустав** (`top`/`bottom`), а не «всегда по нижнему краю». Общий дефолт был незаметен на палочках пилота и давал на настоящих частях: рука вращалась вокруг кисти, бедро — вокруг колена, голень — вокруг стопы;

| Вывод | Следствие |

| `Animation.add_track` / `AnimationLibrary.add_animation` — runtime API | Клипы собираются скриптом, `.tscn` не нужен |

#### Три приёма, которых у меня не было

1. **Пивот = точный центр текстуры**, обе стороны чётные, остальное — паддинг прозрачностью. Тогда `centered=true, offset=0` и вся позиционная арифметика исчезает. Проверяется в **генераторе**, не глазами.
2. **Joint-dot discs** — круглые «пробки» в точках вращения закрывают клиновидные швы при повороте. Прямая цена paperdoll-анимации.
3. **Near/far** — одна текстура руки/ноги используется дважды, дальняя затемняется `modulate`, и **никогда не флипается**.

### 11.10 (позже) — «постоянно разворачивается спиной»: инвертированное зеркало

Ветка: `feature/rigged-units`. Жалоба игрока после запуска пилота: «только когда он ходит в лево или в право он постоянно разворачивается спиной идёт».

**Причина оказалась не в том, что я думал.** Я готовил фикс на гистерезис и мерцание — и оба были настоящими дефектами, но главным был третий.

| | Что было | Что стало |
|---|---|---|
| `_build_view()` | вызывался на **каждом** шаг поворота: 15 узлов и `AnimationPlayer` пересоздавались 20 раз в секунду | только при **смене ракурса**; зеркало — дешёвый `scale.x` |
| Гистерезис | отсутствовал, зеркало щёлкало на границе октантов | `HYSTERESIS_STEPS = 2` |
| **`_apply_mirror()`** | **`sin(dir*45°)` — инверсия** | **`cos(90° + dir*45°)`** |

**Главный баг — инверсия знака.** Горизонталь октанты это `cos(90° + dir*45°)`, а я взял `sin(dir*45°)`, что соответствует **отражённой** оси: октанта 2 (запад) считалась восточной и наоборот. На ходу влево/вправо персонаж отражался не тем боком и шёл боком.

**Как это держалось зелёным — и почему это отдельный урок.** Хелпер теста строил вектор октанты как `(sin(i*45°), cos(i*45°))` — то есть **ту же отражённую ось**; ожидание `posmod(-i, 8)` была согласована с тем же искажением. **Проверка и код совпадали друг с другом, а не с реальностью.** Это тот же класс, что §12 уже ловил дважды: тест, который пересчитывает решение тем же способом, что и проверяет, проверяет себя. Теперь вектор октанты строится одним хелпером `_octant_vector()` для кода и теста, и сверяется с **документированной** конвенцией.

**Первый фикс я поставил не туда.** Проверка «зеркало стабильно на октантах одной стороны» ловит дребезг, но инверсию пропускала: зеркало было стабильным, просто не тем. Добавлена проверка **ориентации** (октанта 6 = восток → `scale.x = +1`, октанта 2 = запад → `−1`) — **доказана мутацией**: возврат `sin(dir*45°)` даёт ровно 2 провала с точным диагнозом.

**Третий баг поймал тест, а не я:** при `target_dir == dir` шаг всё равно делался (`diff == 0` попадал в ветку `step = +1`), юнит **проскакивал мимо цели** и уходил дальше — поворот никогда не сходился. В игре путь закрыт условием в `_process`, но метод зовут напрямую из тестов.

`anim_contract_smoke` 44 → **51**. Регрессия зелёная, `--import` и `--quit` чистые.

**Требуется ручная визуальная проверка:** та же — ходьба влево/вправо должна теперь давать зеркальное отражение, а не разворот.

### 11.10 (позже 2) — «на ходу вниз отворачивается»: −1.8e−16 решает за игрока

Ветка: `feature/rigged-units`. Игрок: «направления хорошо, четко идёт туда куда направляешь; смерть хорошо; но когда идёт вниз, иногда на кадр отворачивается в другую сторону, хотя вектор один и точный».

**Причина — плавающая точка, а не логика.** Горизонталь октанты считается как `cos(90° + dir·45°)`. Для юга это `cos(270°)`, а он в float **не ноль, а −1.8e−16**. Условие `>= 0.0` на таком числе даёт «смотрит на запад» → зеркало включается ровно на октанте 4, где отражать нечего. При ходьбе вниз октанты 4↔5 чередуются, и персонаж щёлкал.

**Правка:** `MIRROR_EPS = 0.35`. При `|cos| < eps` решение **не принимается** — `_mirror` сохраняет прежнее, юнит «скользит» текущим ракурсом. Диагонали дают `|cos| = 0.707`, запас двойной. Скольжение на север/юг игрок принял как достаточное.

#### Агрегатный инвариант спрятал баг — отдельный урок

Я сначала добавил проверку «полный круг 0..7 даёт **ровно 2** переключения зеркала». На баге она **проходила зелёной**: инверсия на октанте 4 симметрична и в агрегате взаимно сокращается (щёлк на 4 компенсируется лишним щёлком на 5). Мутация `MIRROR_EPS → 0` дала провал только на **явной** проверке «октанта 4 не меняет зеркало».

**Правило: агрегатный инвариант («за круг ровно N переключений») не заменяет покоординатную проверку — ошибка, симметричная относительно суммы, в сумме невидима.** Продолжение уже записанного «тест, который пересчитывает решение тем же кодом, что и проверяет, проверяет себя».

`anim_contract_smoke` 51 → **53**, `MIRROR_EPS` доказан мутацией. Регрессия зелёная, `--import`/`--quit` чистые, `runtime_errors_smoke` — 0 скрипт-ошибок.

### 11.10 (позже 3) — «первый раз делает взмах, потом только звуки»

Игрок: «когда атакует то он первый раз делает взмах, и потом просто звуки и видно как отымается здоровье у НПЦ Серого».

**Причина — расхождение бэкендов по контракту, а не ошибка логики.** Удары гейтятся `_impact_timer` и кулдауном, поэтому состояние `"attack"` живёт **дольше одного замаха**, и `play(ATTACK)` зовётся каждый кадр. У спрайт-листов это безвредно: `advance()` циклит фазы, поэтому взмах повторяется сам собой. Риг же при `anim == anim_kind` выходил из `play()` раньше — и **доигранный одноразовый клип навсегда замирал на последнем кадре**.

**Правка:** `play()` перезапускает одноразовый клип, если тот уже доигран (`_clip_finished()`), но **не** перезапускает замороженный (`_frozen` от `freeze_last_frame`) — иначе `play(DYING)` в состоянии `"dead"` снова запустил бы падение и мёртвый шевелился.

#### Две ошибки в самой проверке — обе опаснее, чем был баг

1. **Сверял позу, а не факт рестарта.** Клип замаха возвращается в начальную позу на последнем ключе (`ArmFront: −10° … −95° … 40° … −10°`), поэтому первый и последний кадр **неразличимы**, и проверка «поза изменилась» прошла бы и на сломанном коде. Теперь сверяется время клипа плюс проход через замах.
2. **Хелпер искал кость по неверному пути** (`Torso/...` вместо `Hip/Torso/...`) и при промахе **молча возвращал 0.0** — проверка «поза удержалась» проходила **вхолостую**. Это уже знакомый класс из §12, только тише: молчаливое значение-заглушка вместо провала. Теперь промах — ошибка теста.

`anim_contract_smoke` 53 → **57**, рестарт **доказан мутацией** (возврат старого условия даёт 2 провала с диагнозом «время 0.500»). Регрессия зелёная, `runtime_errors_smoke` — 0 скрипт-ошибок.

## 26.10 — музыка: плейлист вместо «трека на ситуацию»

Ветка: `feature/agent-audio-replacement`. **Код и автотесты зелёные, В ИГРЕ НЕ ПРОВЕРЕНО.**

### Почему переделали

Прежняя схема играла «трек на контекст»: меню — `music.menu`, мир — случайный из
`explore_1/2`. Для треков по 3+ минуты это неверно: любой переход (меню → герой →
мир) резал трек на середине. Замеры: 184–208 с на трек, громкость −15.2…−16.7 LUFS,
то есть разброс 1.5 dB — выравнивать по трекам не нужно.

### Как теперь

- **Одна очередь на весь сеанс**, старт при запуске игры с трека 1:
  `menu_main → town_rest_1 → town_rest_2 → ancient_1 → ancient_2 →
  explore_1 → explore_2 → combat_1 → menu_main → …`
- Каждый трек играет целиком, **луп выключен** (иначе очередь не дойдёт до
  следующего). Переход — кроссфейд 2.5 с, за 2.5 с до конца.
- Смена сцены, вход в интерьер и Esc-пауза очередь не трогают: узлы в корне
  дерева, `Timer` с `PROCESS_MODE_ALWAYS`. Возврат в меню позицию не сбрасывает.
- Контекстных переключений (бой/город/древние) больше нет: `music.*`-ключи и
  механизм `MusicDB.play(key)` удалены. Остались `start_playlist()`, `next_track()`,
  `current_index()`, `current_file()`.

### Файлы

- `assets/audio/music_db.json` — v2: `bus`, `gain_db`, `crossfade`, `playlist`.
- `scripts/music_db.gd` — очередь, два плеера для кроссфейда, таймер на
  `length − crossfade`, страховка на `finished` (если таймер опоздал).
- `main_menu.gd`, `character_select.gd`, `game.gd` — `start_playlist.call_deferred()`;
  повторные вызовы идемпотентны.
- `tests/audio_smoke.gd` — плейлист: 8 файлов, старт с `menu_main.ogg`, без дублей,
  длины > 150 с, луп выключен; повторный старт не сбрасывает индекс; `next_track()`
  двигает очередь; `MusicDB.play(` в коде не осталось.

### Проверки

- `audio_smoke`: **1104 проверки, 0 провалов** (в том числе живой запуск очереди
  и переход на трек 2).
- `runtime_errors_smoke`: без `SCRIPT ERROR`.
- `--headless --quit`: чисто.

**Требуется ручная проверка игроком:** запуск → играет тема меню; через ~3 минуты
кроссфейд во второй трек; меню → выбор героя → мир без перезапуска; Esc-пауза —
музыка продолжается; слайдер музыки работает.
