# Changelog

Все изменения проекта Allods Home (Godot версия) документируются здесь.

Формат основан на [Keep a Changelog](https://keepachangelog.com/).

## [0.6.0] — 2026-09-15

### Added
- **Каталог предметов инвентаря** (`inventory_catalog.gd` + кнопка «Предметы…» в редакторе): 491 иконка из `assets/inventory` распределяется мышкой по категориям «тип + материал»
- Категории с рангами качества: оружие, броня, щиты, амулеты, кольца, луки, арбалеты — по материалам (дерево, кожа, плотная кожа, бронза, золото, железо, сталь, мифрил, адамант, метеорит, кристалл, драконья кожа); плюс одежда/оружие мага, свитки, книги умений, зелья, квестовые (особые)
- Сохранение каталога в `assets/maps/inventory_catalog.json` (в git): `{файл.png: {cat, quality}}` — по `quality` можно сравнивать предметы
- **Экипировка героя кликом** по слотам инвентаря (исправлен mouse_filter — иконка больше не перехватывает клик)
- Тестовый инвентарь наполнен железным набором по раскладке пользователя (мечи/булавы/копья/топоры/щиты/броня)
- **Карта кадров меча** пользователя: heroes/swordsman — направление-мажор, 8 направлений (idle 16 → move 8×10 → attack 8×7 = 152); в валидаторе — все кадры сходятся с раскладкой пользователя

### Changed
- `unit_anim.gd`: поддержка двух схем — 5 направлений + зеркало правых (unarmed) и 8 направлений направление-мажор (оружие); стойка у оружия из отдельного idle-блока
- Единая схема наборов оружия: `idle 16, move 10×8, attack N×8` (N=(frames−96)/8 — сходится для всех геройских наборов)
- Дефолт героя — без оружия (`heroes/unarmed`)

## [0.5.0] — 2026-09-15

### Added
- **Система анимаций персонажей** (`unit_anim.gd` + `unit_db.gd`): покадровая анимация юнитов из `assets/units` с 8 направлениями и фазами (движение/атака/смерть/ожидание)
- **База юнитов** `units_db.json` (сгенерирована из `units.txt`): 89 наборов — герой (тяжёлая броня), герой лёгкой брони (heroes_l), люди (humans), монстры (monsters); фазы, тайминги, размер/якорь из оригинальных данных
- **Анимация героя по экипировке**: броня (тяжёлая → `heroes/`, лёгкая → `heroes_l/`) × оружие (меч/топор/булава/копьё, двуручные `2h`, лук, арбалет, посох, маг) × щит (`_`-суффикс)
- **Анимации монстров** в `enemy.gd` (набор задаётся через `anim_set`, напр. `monsters/orc`)
- **Тестовый инвентарь**: все виды брони (кожаная…кристалл, лёгкая/тяжёлая) и оружия (одноручное/двуручное/дальнобойное/посох/кулаки) + щит; клик по предмету — экипировать героя
- Управление экипировкой: `armor_kind`/`weapon`/`two_handed`/`has_shield` у игрока, `anim_set_name()` вычисляет набор анимаций

### Changed
- Спрайт героя и монстров заменён со статичного на анимированный `UnitAnim` (8 направлений, фазы)

## [0.4.1] — 2026-09-15

### Fixed
- **Анимация объектов map-objects**: большинство объектов (pine2/pine3, elka2/3, vallen2/3, oak2/3 и др.) не анимировались — в базе `object_db.json` для них были записаны данные dead-вариантов (1 кадр) вместо живых (7 кадров), потому что генератор не учитывал наследование `Parent` из `objects.txt`
- Перегенерирована база: `frames` берётся из живой версии объекта (с учётом цепочки `Parent`), `dead`/`fire` — из ссылок живого объекта; теперь 53 объекта с кадрами >1
- Объекты без явного расписания анимации (`AnimationFrame`) теперь анимируются **по порядку кадров** (дефолтный тайминг 0,1 с/кадр) — анимируются всё, у кого больше одного кадра

## [0.4.0] — 2026-09-15

### Added
- **Объекты карты из map-objects**: 77 оригинальных объектов (деревья, кусты, камни, статуи, заборы…)
- **База объектов** `object_db.json` (сгенерирована из оригинала `objects.txt`): кадры, расписание анимации, размеры/якорь, dead/fire-связи
- **Покадровая анимация объектов** в реальном времени (8 объектов с анимацией; синхронно по `AnimationTime/AnimationFrame`)
- **Разрушение объектов магией с уроном по области**: огненный шар (радиус 40) и молния (радиус 60) наносят урон объектам; при HP ≤ 0 объект переключается на `dead`-текстуру (пень/руины)
- **Неразрушаемые объекты**: у кого нет `dead/`-папки — урон игнорируется
- **Двухслойный рендер карты**: слой земли + слой объектов; объект «стоит» на земле, а не на сером фоне
- **Земля под объектом** (`under_tiles`): сохраняется в JSON карты, ластик по объекту возвращает её
- В панели «Настройки» объекты помечаются бейджами **A** (анимирован) / **R** (разрушаемый)
- Скрипты: `object_db.gd`, `map_object.gd`

### Changed
- Спецификация объекта: `{"kind":"object","obj":"имя"}` (старые записи с `path` поддерживаются)
- Палитра наборов текстур читается из **`res://assets/maps/map_editor_palette.json`** (была в user://) — наборы синхронизируются через git и используются обоими местами (редактор + игра)
- Кнопка «Новая» снова подтягивает наборы из палитры (не сбрасывает в дефолт)

### Fixed
- **Зависание «Залить область»**: заливка пустой области уходила в бесконечность за границы карты (в `tile_id_at` за границей возвращается -1 = «пусто»); добавлена проверка границ в цикле
- Категории «Строение», «НПЦ», «Спавн» не были видны в настройках текстур (циклы были на 5 категорий, а не 8)
- Серый фон под объектами на карте (объект заменял клетку земли — теперь рендер двухслойный)

## [0.3.0] — 2026-09-14

### Added
- **Декодер оригинальных карт .alm** (`alm_loader.gd`): магия "M7R", ширина/высота, 2 байта/тайл × 2 слоя; старт тайл-секции ищется по пространственной связности
- **Прямой рендер .alm**: `byte[1]` = тип рельефа (0-3 tile1-4, 16-40 вода), `byte[0]` = variant+ряд из пользовательской палитры; вода/скала непроходимы
- **Подключение карты к игре**: `main` грузит `my_map.json` через `CustomMap`, спавн героя берётся из карты (тип «Спавн»), миникарта поддерживает CustomMap
- **8 типов terrain**: Трава, Земля, Песок, Вода, Скала, **Строение, НПЦ, Спавн**
- **Редактор карт** (`map_editor.tscn`): кисть по сетке (1-3 тайла), **заливка области**, **ластик**, **undo (Ctrl+Z)**, управление размером карты, JSON save/load, камера (WASD + зум)
- **Настройки текстур**: для каждой категории собирается набор текстур (tile1-4 × варианты × ряды) с сохранением в палитру
- Игра использует набранные в редакторе текстуры terrain (регионы по `byte[1]`)

### Changed
- Палитра текстур из пользовательских наборов применяется и в .alm-рендере
