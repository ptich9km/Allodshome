## [0.15.0] — 2026-09-22

### Added (редактор переходов terrain: 7+2 типа, tile5/6/7, генератор карт)
- **Система terrain-типов расширена до 7+2**: Трава (tile1), Почва (tile5),
  Песок (tile6), Вода (tile3), Горы (tile2), Дорога (tile4), Грязь (tile7) +
  Строение/Спавн (цвет-плейсхолдеры). WalkTable: почва 8, песок 12, грязь 14.
- **Визуальный редактор переходов** (`scripts/transition_editor.gd`, кнопка
  «Transitions» в редакторе карт): сетка 3×3 (центр = тип A, 8 клеток =
  направления N/NE/E/SE/S/SW/W/NW), клик по ячейке — палитра тайлов типа A;
  центральная ячейка (interior) редактируется и сбрасывается.
- **База переходов** `assets/maps/transition_db.json`: **336 правил** + interior
  для всех 7 типов. 96 правил импортированы из 9+ карт разработчиков
  (`pvm/`, скриптом `analyze_dir_transitions.gd`), остальные — дефолтные;
  диагонали наследуются от кардинальных. `file` в правиле = палитра
  (песок/грязь выбираются из tile1), для .alm генераторы пересчитывают по типу A.
- **Импорт переходов из .alm прямо в редакторе**: `_on_import_alm` сканирует
  `assets/maps/pvm/` (DirAccess, все `*.alm`/`*.ALM`), считает статистику
  границ по **8 направлениям** + interior, заполняет правила самым частотным
  тайлом для каждой пары.
- **Плитки tile5/6/7** (`tests/gen_tile_placeholders.gd`): PNG 32×32 для палитры
  редактора (224 на тип, `tiles/tileN-VV_RR.png`) + BMP-полосы 32×448 для
  рендера (`tileN-VV.bmp`). BMP пишется вручную 24-бит bottom-up (в Godot 4
  нет `Image.save_bmp`; top-down Godot не импортирует). Текстуры — процедурный
  шум по базовому цвету, не плоская заливка.
- **Рендер tile5/6/7**: `alm_map._build_atlas` — файлы 1..7, 16 вариантов
  каждый; `custom_map._load_tile_region` — кламп 0..7 (был 0..4 → грязь
  рендерилась как дорога); `texture_settings.gd` — вкладки tile1..tile7 +
  «Объекты».
- **Генератор умных карт** (`tests/gen_smart_map.gd`): отдельные шумы для
  земли/почвы/песка/грязи (пороговые доли ~8/6/4% поверх травы), читает
  336 правил из transition_db, `_spec_for_type` пересчитывает file по типу A.

### Changed
- `gen_alm_map.gd` / `gen_smart_map.gd`: `_interior`/`_edge` берут spec из
  `transition_db.json` с пересчётом `file = TERRAIN_FILE[type]` (0→tile1, 1→tile2,
  2→tile3, 3→tile4, 4→tile5, 5→tile6, 6→tile7) — вариант/ряд из правила.
- Удалены захардкоженные `scripts/tile_directions.gd` и
  `assets/maps/tile_directions.json` — заменены на transition_db.json.

### Verified (headless)
- `tests/test_transitions.gd` → `RESULT:OK transition_editor+db`: 336 правил,
  file-маппинг, 224 PNG × 3, BMP 32×448, roundtrip `tile_from_spec`/`tile_type`
  для типов 4/5/6, полнота пары 4↔5 (почва↔песок).
- `tests/test_import_smoke.gd` → `RESULT:OK import_smoke`: сканирует `pvm/`,
  грузит 11 `.alm` (типы 0-3), edge-статистика 410974 клеток, 96 уникальных
  ключей — та же логика, что `_on_import_alm`.
- `tests/gen_alm_map.gd` / `gen_smart_map.gd` — читают 336 rules, генерируют
  карты OK.

## [0.14.0] — 2026-09-18

### Added (магия: расшифрован реестр снарядов, панель 24, книги, свитки мага)
- **Панель магии — каноничные 24 книжные магии**: всегда 2 ряда по 12 ячеек,
  порядок `docs/rom2-ref/spells.txt` (слот 1 = Fire Arrow … слот 24 =
  Stone Missile). Выучено — иконка снаряда магии поверх `spellback` +
  подсказка (название, сфера, мана/заряды); не выучено — пустой квадрат с
  подсказкой «какая магия здесь учится».
- **Реестр снарядов `assets/projectiles/projectiles.reg` расшифрован**:
  каталог (Global + Projectile0..30, по 32 байта: имя/offset/поле/флаг) +
  секция атрибутов по 32 байта (`File` → путь, `Phases`, `RotationPhases`,
  `Palette`, `Width/Height`, `Homing`, `Flip`, `A16`, `SFX`) + таблица
  строк-путей в конце файла. 31 снаряд, из них 24 «волшебных» — по одному на
  книжную магию.
- **Иконки панели — реальные спарйты магий** из каталога `assets/projectiles`:
  `SpellDB.projectile_icon()` выбирает самый «полный» кадр (по непрозрачным
  пикселям) `sprites-NNN.png` с кэшем. Временные `assets/spells/spell_00..23.png`
  удалены.
- **Заклинания Книг Сфер** (Curse/Slow/Light…) идут следом за каноничными 24
  с иконкой свитка из `item_db`.
- **Прицельное чтение свитков МАГА**: двойной клик по свитку в складе —
  анимированный курсор `cast/` + подсказка, клик выбирает цель (враг для
  атаки/области/стены; герой или союзник-НПЦ/наёмник для лечения/защиты),
  ПКМ/ESC отменяет без расхода. Свиток применяется 1 раз и списывается,
  ману не тратит и в панель не попадает.
- **Каст с панели**: клик по выученной магии кастует по курсору — маг платит
  ману (универсальный КД 0.8 с), свитковая ячейка тратит заряд (израсходована
  — ячейка гаснет). Эффекты: снаряд с анимацией фаз из папки, лечение, бафф,
  стена, телепорт, урон по области (по объектам карты и врагам).
- **Защитные баффы** (Protection от стихий / Shield / Bless):
  `Game.apply_shield/shield_reduce/tick_shields` — поглощают входящий урон в
  течение времени; работают у героя, врагов, НПЦ и наёмников.
- **Книги магии**: «Book Fire Arrow» (одно заклинание) и «Book Fire» (вся
  сфера) — учатся двойным кликом по ячейке склада (только маг), книга
  расходуется. `SpellDB.spell_of_book/book_key_for_spell/make_book_item`;
  книга одного заклинания синтезируется (в item_db её не было).
- **Магазин — полка «Свитки»**: свитки и супер-свитки в одну полку по цене;
  книги магии на полке только для мага (по мере цены от
  `item_db`). `SpellDB.catalog_spells()` — порядок сфер, затем цена.
- **Школа мага в создании героя**: выбор склонности у мага задаёт школу магии
  (сфера +20, `Game.hero_start_book`) — на старте в склад кладётся книга
  простейшего заклинания этой сферы (`SpellDB.simplest_spell_of_sphere`).
  Пресеты магов нейтрализованы (навыки 5/5/5/5/5) — развитие только школой.
- **ВРЕМЕННО (отладка магии) `Game.debug_magic = true`**: маг на старте знает
  все 24 книжные магии — панель заливается иконками, каст проверяется без книг.

### Fixed
- База заклинаний: битые привязки снарядов — `Blizzard→steam`,
  `Summon→teleport`, `Animate_Dead→poison_d` (папок `blizzard`/`magic` нет);
  у всех 24 книжных магий иконка читается из существующего файла кадра.
- Свитковое заклинание в панели больше не «застревает» с нулём зарядов
  (последний заряд тратится — ячейка исчезает).

### Verified (headless)
- `test_hero_select.gd` — RESULT:OK.
- Все 24 слота панели находят существующий кадр снаряда (Fire_Arrow→firebolt,
  Stone_Missile→meteorit, Blizzard→steam, Summon→teleport,
  Animate_Dead→poison_d).

## [0.13.28] — 2026-09-17

### Added (ОПЫТ и НАГРУЗКА — по формулам разработчиков)
- **ОПЫТ** в панели характеристик: суммарный опыт по 10 навыкам (5 оружия +
  5 магии). Механика как у разработчиков (UnityAllods MapHuman/MapUnit):
  - за **удар оружием**: `exp = урон/HPмакс × Experience цели × (1 + Mind/100)`,
    при убийстве ×2, опыт идёт в навык оружия (меч/топор/булава/копьё/стрельба);
  - за **заклинание**: опыт в сферу магии (огонь/вода/воздух/земля/астрал);
  - **навык растёт от опыта**: `exp = (1.1^skill − 1) × 1000`,
    уровень = `floor(log₁.₁(exp/1000 + 1))` — чем выше навык, тем медленнее рост.
- **НАГРУЗКА** в панели: суммарный вес предметов в инвентаре / ёмкость
  (30 + ТЕЛО×10). Перегруз снижает скорость героя до 0.5× (как в ROM2:
  «вес владений влияет на скорость»). Скорость пересчитывается при
  добавлении/удалении предметов.

## [0.13.14] — 2026-09-17

### Fixed (монстры больше не «бегают вокруг героя»)
- **Причина**: при входе в состояние `attack` монстр не гасил скорость —
  инерция от погони (через `move_and_slide`) несла его МИМО игрока; вылетев
  за радиус боя, он возвращался в `chase`, разворачивался и снова
  проскакивал. Отсюда «бегает вокруг, то туда, то сюда» вместо ударов.
- **Фикс**: при переходе `chase → attack` скорость обнуляется
  (`velocity = Vector2.ZERO`), и в состоянии `attack` между ударами держится
  стоп (`move_toward(ZERO)`) — как у героя и наёмника. Монстр подходит,
  останавливается и бьёт в упор.

- Удалён мёртвый код проходимости из `AlmLoader` (`is_walkable`,
  `is_walkable_type`, `speed_factor_type`, `height_level`).

  - Из info: имя/автор карты, угол солнца (solar), время суток, счётчики сущностей
- **Рельеф**: каждый тайл-квад 32×32 поднимается на высоту углов (int8 из секции heights), текстура растягивается под наклон; атлас всех используемых ячеек (файл-вариант-ряд) собирается в одну текстуру загрузчиком
- **Свет от солнца** (методика jewalky/Allods16): угол солнца из info (.alm), нормаль квада через cross-произведение, яркость `|n·sun|·64+96` с контрастом; плоский террейн ~1.0, склоны затемняются
- **Препятствия** (секция obstacles → objects.txt): дерево/камень/статуя с якорем (cx,cy) и анимацией кадров (sprites-001..00N), поднимаются на высоту рельефа, y-sort
- **Строения/здания** (секция id=4 → structures.reg): распознаны 19 строений Kids3 — деревня в центре (церковь/Saving Place, трактир Inn 1, магазин Shop 2, колодец Well 2), мост, хижины, руины, костёр; конвертация спрайтов зданий (house.256 → PNG) выполнена, рендер в процессе
- **Формат спрайтов .256 расшифрован**: палитра 256×4 байта, кадры [w][h][len][RLE], счётчик кадров в конце файла (старший бит = флаг палитры); RLE-токены: `0x00-0x3F` серия пикселей, `0x40-0x7F/0xC0-0xFF` вертикальный пропуск, `0x80-0xBF` горизонтальный пропуск
